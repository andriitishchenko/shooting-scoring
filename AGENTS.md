# Agent Instructions

## Documentation language and style

Write and maintain all project documentation in English according to ASD-STE100 Simplified Technical English (STE).

This rule applies to user guides, setup instructions, technical references, API documentation, test procedures, release notes, examples, and explanatory code comments. It also applies when an agent edits an existing document. Rewrite the changed text in STE. Do not assume that existing text follows STE.

Use ASD-STE100 Issue 9 (January 2025) and its dictionary as the writing reference. Do not search the web for the specification during routine documentation work.

Apply these rules when you write:

- Use approved words with their approved meanings and parts of speech. Check the STE dictionary when it is available.
- Use one approved word for one meaning. Do not add synonyms for variety.
- Write short, direct sentences. Put one main instruction or fact in each sentence.
- Use the active voice. Use the imperative form for procedures. Give one action in each procedure step.
- Use present tense where possible.
- Avoid idioms, slang, contractions, vague pronouns, and unnecessary words.
- Use technical nouns and technical verbs only when they are necessary. Use each term consistently and explain it when readers need a definition.
- Keep code, commands, API names, data fields, and exact product interface labels unchanged. Explain them in STE English.

Do not claim that text complies with ASD-STE100 based only on how simple it looks. Check the text against the Issue 9 writing rules and dictionary when possible. If you cannot check a word or rule, use clear, direct English and identify the item that needs review.
